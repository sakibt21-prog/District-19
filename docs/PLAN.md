## Stack

| Layer | Choice |
|---|---|
| Framework | Next.js (App Router), TypeScript |
| Styling | Tailwind CSS with the design tokens as CSS variables |
| Motion | Framer Motion for component and scene motion; GSAP (Flip, ScrollTrigger, SplitText) for the route transition, scroll reveals and headline splits |
| Data | Supabase Postgres with row-level security |
| Photos | Supabase Storage, public read bucket, admin-only write |
| Auth | Supabase Auth, cookie sessions through `@supabase/ssr` |
| Hosting | Vercel |

## Routes

Public:

- `/` — hero rail (New Releases), featured collections, shirts, pants ("Try the Look"), shoes (float), best sellers, brand introduction, footer
- `/shirts`, `/pants`, `/shoes` — category pages with search, filters (size, colour, price, in stock, sale, new) and sorting
- `/product/[slug]` — rotating product view, gallery, variants, size guide, related products
- `/cart`, `/checkout`, `/order/[id]` — cart, Bangladesh checkout, order confirmation
- `/search`

Admin (all under `/admin`, none linked from the shop):

- `/admin/login`
- `/admin` — overview counts: total products, total orders, new orders, published, out of stock
- `/admin/products`, `/admin/products/new`, `/admin/products/[id]` — create, edit, delete, publish, feature, inventory, photos
- `/admin/looks` — upload a model photo and attach products, for the "Try the Look" scene
- `/admin/orders`, `/admin/orders/[id]` — customer, items, payment method, status updates

## Database

| Table | Holds |
|---|---|
| `products` | name, slug, category (shirt, pant, shoe), description, price, sale price, status (draft, published), featured, new release |
| `product_images` | storage path, sort order, is primary, role (front, back, gallery) |
| `product_variants` | product, size, colour, colour hex, SKU, stock quantity |
| `looks`, `look_items` | model photo and the products in that outfit |
| `admin_users` | auth user id, role |
| `customers` | name, phone, email |
| `orders` | customer, delivery address (division, district, area, street), delivery zone and fee, payment method, payment status, transaction id, order status, totals |
| `order_items` | order, variant, name and price as sold, quantity |

Inventory lives on `product_variants.stock_quantity`. Placing an order reduces stock inside one database function so two buyers cannot take the last item.

## Admin security

- Sign-in through Supabase Auth. No public sign-up page; the first admin is created by a seed script, later ones from inside the dashboard.
- Three server-side checks, none of which depends on the URL being secret:
  1. Middleware redirects any `/admin` request without a session.
  2. The admin layout re-reads the user on the server and checks `admin_users`.
  3. Every server action that changes data checks again before touching the database.
- Row-level security: anyone can read published products; only rows in `admin_users` can write products, images, variants, looks, or read orders. Storage has the same rule for uploads.
- The service-role key is used only in server code and never shipped to the browser.

## Checkout for Bangladesh

- Phone in `01XXXXXXXXX` form, division and district pickers, delivery fee by zone (inside Dhaka, outside Dhaka), prices in BDT.
- Cash on Delivery: fully working.
- bKash and Nagad: see "Decisions needed". No payment is ever marked paid without real confirmation.

## Decisions needed from the owner

1. **Supabase project.** A project URL, anon key and service-role key are needed in `.env.local` before the admin, uploads or orders can be tested.
2. **bKash and Nagad.** Real gateway integration needs merchant API credentials from each provider. Without them the honest option is manual payment: the customer sends money to the shop number, enters the transaction ID at checkout, and an admin confirms it before the order is marked paid.
3. **Photos.** The reel look depends on cut-out photos (transparent background): products shot front and back, and full-body models for "Try the Look". Until real photos are uploaded the shop would run on plain placeholder shapes.
